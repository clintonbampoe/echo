## Running the seeder

The seeder is not meant to run on the host. It runs as part of the Aspire
AppHost, or as a one-shot container via Docker Compose.

### Aspire (normal development)

The seeder is a resource in the AppHost. Start the AppHost and the seeder
runs when its dependencies are healthy:

```bash
dotnet run --project src/Echo.AppHost
```

To re-run it after a first run, use the Aspire dashboard to restart the
`seeder` resource, or stop and start the AppHost.

To reset the database before a run, set the option in the AppHost's
`appsettings.Development.json` (or via Aspire parameters — see below).

### Docker Compose (one-shot)

```bash
# Start the database
docker compose up -d db

# Run the seeder once and exit
docker compose run --rm seeder

# Reset and re-seed
docker compose run --rm seeder Seeder:Reset=true

# Custom seed
docker compose run --rm seeder Seeder:Seed=12345

# Different volume
docker compose run --rm seeder Seeder:BigMembers=1000
```

### Overriding options

Options can be overridden the same way in either environment — via
environment variables or CLI args, whichever the AppHost / Compose file
passes through.

Environment variables:

```
Seeder__Reset=true
Seeder__Seed=99
Seeder__BatchSize=500
Seeder__BigMembers=1000
```

CLI args:

```
Seeder:Reset=true
Seeder:Seed=99
```

In Aspire, add these to the seeder resource's environment in `AppHost.cs`,
or pass them as parameters when the resource is launched.

## Regenerate the admin list

If the emails in the table above don't match what's in your database, run this
against the seeded DB:

```sql
SELECT
    c."Name"         AS "CongregationName",
    u."Name"         AS "UserName",
    u."EmailAddress" AS "UserEmail"
FROM "Congregations" c
LEFT JOIN "Users" u
    ON u."CongregationId" = c."Id"
   AND u."DeletedAt" IS NULL
WHERE c."DeletedAt" IS NULL
ORDER BY c."Name", u."Name";
```

## Verify the seed

Run these after seeding. All three should return zero rows.

```sql
-- Every converted visitor must have a Members row
SELECT v."PersonId"
FROM "Visitors" v
LEFT JOIN "Members" m ON m."PersonId" = v."PersonId"
WHERE v."ConvertedAt" IS NOT NULL AND m."PersonId" IS NULL;

-- Person.Kind must agree with the side tables
SELECT p."Id", p."Kind"
FROM "People" p
LEFT JOIN "Members" m ON m."PersonId" = p."Id"
WHERE (p."Kind" = 'Member'  AND m."PersonId" IS NULL)
   OR (p."Kind" = 'Visitor' AND m."PersonId" IS NOT NULL);

-- No duplicate organization names within a congregation
SELECT "CongregationId", "Name", COUNT(*)
FROM "Organizations"
GROUP BY "CongregationId", "Name"
HAVING COUNT(*) > 1;
```

Count of congregations:

```sql
SELECT COUNT(*) FROM "Congregations" WHERE "DeletedAt" IS NULL;
-- expect 11 (1 big + 10 small)
```

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `duplicate key value violates unique constraint` | Rerunning without `Reset=true` | `docker compose run --rm seeder Seeder:Reset=true` |
| FK violation on `Visitors` or `Members` | Bad FK target in faker | File an issue; don't retry |
| `DateTime with Kind=... cannot be written` | Kind mismatch or wrong `NpgsqlDbType` | Check `Copy/*.cs` and the faker rule |
| Seeder hangs on a COPY | Batch size too large | Lower `Seeder__BatchSize` to `500` |

Last resort (Docker):

```bash
docker compose down -v
docker compose up -d db
docker compose run --rm seeder Seeder:Reset=true
```

Last resort (Aspire): stop the AppHost, run `docker compose down -v` against
the containers it manages, then restart the AppHost.
