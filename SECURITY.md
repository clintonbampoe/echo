# Security Policy

## Reporting a vulnerability

**Do not** file a public GitHub issue for critical security vulnerabilities. This puts all users at risk—even if the project isn't deployed yet, we still take security seriously.

Instead, use one of these private reporting channels:

1. **Email**: Send details to **clintbamp+echo@gmail.com**.
   This goes directly to the core maintainer's inbox. We'll acknowledge receipt within 48 hours.

2. **GitHub Private Security Reporting** (preferred if enabled):
   Click the **"Security"** tab at the top of the repository, then **"Report a vulnerability"**.
   This creates a private advisory that only the repository admins can see—no public visibility until we decide otherwise.

### What to include in your report

- A clear description of the vulnerability.
- Steps to reproduce it (if possible, without exposing sensitive data).
- The potential impact (e.g., "information disclosure", "privilege escalation").
- Any suggested mitigation or fix (if you have one).

### How we handle it

1. We'll confirm receipt within 48 hours.
2. We'll investigate and validate the issue.
3. We'll work on a fix and coordinate with you on the best way to address it.
4. We'll give you credit for the discovery (unless you prefer to remain anonymous).

### Questions?

If you're unsure whether something is a security issue, err on the side of caution and report it privately. We'd rather review a false positive than miss a real vulnerability.

Thank you for helping keep Echo safe—even at this early stage.
